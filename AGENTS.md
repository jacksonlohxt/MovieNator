## Implementation pointers

- The mock-safe engine, local API, browser route, contracts, fixtures, and validation commands are documented in `docs/implementation.md`; the Google runtime scaffold and read-only packet boundary are documented in `docs/google-agent-runtime.md`.
- The default regression gate is `npm test && npm run check`; it requires no credentials or external services.
- Phase 5 deployment, runtime-mode validation, Secret Manager seam, safety budgets, audit events, and operator-only Cloud Run/Agent Runtime actions are documented in `docs/phase5-deployment.md`; no cloud mutation is part of repository validation.
- The default Phase 3 partner path is the credential-free local `mock-provider`; live partner registration and required operator inputs are documented in `docs/partner-integration.md`.
- Phase 4 worker-owned state mutations are lease-fenced by lease ID, with heartbeat renewal and stale-owner rejection in `src/engine.js` and `src/store.js`; bounded tool budget scope eviction is implemented in `src/tool-registry.js`.
- `src/producer-consolidation.js`, `test/producer.test.js`, and `/v1/producer-source-bundles` define the strict bounded Producer Intake slice that emits the PRD-target `producer-intake-decision-packet@1` contract (`PRODUCER_PACKET_SCHEMA`): one `primary_screenplay` and up to twelve PDF/TXT sources produce stable source hashes, a source/version manifest, the full allowlisted classification set (including `source_implied_inference` and explicitly recorded `decision`) and evidence-state set (including `recorded_decision`, `stale`, `unavailable`), conflicts, citations, the full provenance object (`contract_version`, `bundle_manifest_hash`, `source_manifest_hash`, `grounding_strategy`, `fallback_used`, `retention_state`), and read-only Markdown/JSON/CSV handoff exports. `production_elements`, `cast_role_demands`, and `department_requirements` are populated by deterministic, source-grounded pattern extraction that generalizes to any bounded bundle (not just the seeded Northline fixture); see the `deriveProductionElements`/`deriveCastRoleDemands`/`deriveDepartmentRequirements` helpers. Packet `status` is content-derived at build time (`succeeded`, `source_gap` when the primary screenplay establishes no scene but other content exists, `failed` when nothing can be established at all); `expired` is a separate read-time overlay from `applyProducerPacketRetention(packet, { now, retentionTtlMs })`, which is a no-op unless a caller supplies an explicit bounded TTL (local demo mode declares none by default) and is not yet wired into a GET route. The older free-label `/v1/producer-packets` multipart route remains a separate, unrenamed `producer-decision-packet@1` compatibility alias (`PRODUCER_PACKET_SCHEMA_LEGACY`); it does not emit the strict PRD fields. The compliance-trigger register described in `docs/prd.md` remains an explicitly out-of-scope, still-open Captain decision.
- Producer packet creation is asynchronous and immutable: `src/producer-engine.js` (`ProducerPacketEngine`) and the `producerRuns`/`producerRunEvents` collections in `src/store.js` queue one run per `packet_id` (content-derived for a first attempt, freshly minted for a retry child) that advances `accepted` -> `queued` -> `running` -> a terminal `succeeded`/`failed` state; `POST /v1/producer-packets` and `POST /v1/producer-source-bundles/{bundle_id}/packets` return `202 Accepted` immediately (never build the packet in the request), `GET /v1/producer-packets/{packet_id}` returns a bounded pending/failed projection until the run succeeds, `GET .../events` is the SSE progress stream, and `POST .../retry` only ever creates a new child run (`parent_packet_id` link) and never mutates the original terminal run. Test this surface in `test/producer-run.test.js` (not `test/producer.test.js`), using `app.producerEngine.waitForIdle(packetId)` to await completion and `createApp({ producerBuilder })` to inject a failing builder for retry tests.
- The Producer Intake Decision Packet is the browser's primary tab (`web/index.html` `#producer-section`, default `data-workflow="producer"`); Script Brief and Audience Data Readiness are sibling compatibility tabs, all switchable from one always-visible tab list (no `<details>` gate). The producer flow is two-step against the existing bundle/packet routes: upload+label posts `/v1/producer-source-bundles` and renders the source manifest immediately, then a second `decision_context`-aware submit posts `/v1/producer-source-bundles/{id}/packets`. `web/app.js` renders every packet evidence row (facts, scene index, conflicts, decision/question register, gaps, rights/access, the merged schedule+budget ledger) through one generic `renderProducerEvidenceList` that surfaces owner, priority, evidence state, both-sided conflict assertions, and next actions; it never uses `innerHTML`.
- `test/producer-browser-e2e.test.js` is the real-browser (Playwright/Chromium) E2E for the seeded four-file Northline fixture; `playwright` is a devDependency and reuses whatever Chromium build is already cached locally (no network fetch when a compatible cached build exists). It launches its own `createApp` server per test, hard-bounds the test with a `timeout` option, and `t.skip()`s instead of failing if no local Chromium build is available, so `npm test` stays deterministic when offline.
- Two real, accepted-SDK Google call paths exist and are covered end-to-end against injected/mock transports in `test/gemini-rest.test.js` and `test/google-runtime.test.js`: the raw REST `generateContent` path in `src/gemini-rest.js` (Script Brief/Audience Data Readiness), and the `@google/genai` Interactions API path in `src/producer-agent-boundary.js` (`createManagedClient` builds a real `GoogleGenAI` instance; construction is network-free, only `client.interactions.create(...)` is live). `createApp` (used by nearly all tests) never performs a live readiness check by itself; only `startServer` in `src/server.js` does, running one real awaited Gemini preflight at boot when Google is enabled and fully configured, plus a bounded periodic recheck so readiness does not silently go stale after `GEMINI_READINESS_MAX_AGE_MS`. A declared live `RUNTIME_MODE` (`adc_local`/`deployed_identity`) whose preflight fails causes `startServer` to fail closed at boot rather than serving mock traffic. The `GOOGLE_GEMINI_READINESS` env var is informational only and is never read as authority by application code. `npm run google:preflight` (`scripts/google-preflight.js`) is the one operator-run command that makes a real credentialed call; it is intentionally excluded from `npm test`/`npm run check`/`npm run check:docs`. The full operator sequence for a live call and a public Cloud Run URL, plus the exact `/readyz` evidence required before claiming either is live, is in `docs/operator-runbook.md`; `deploy/cloud-run.yaml` is a structurally valid manifest (checked by `test/phase5.test.js`) with only `<OPERATOR_SELECTED_...>` placeholders.
